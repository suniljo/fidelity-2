==========================
Build & Deployment Process
==========================
Development Team - writes the source code of the Project  - Code Repository

1) Take latest source code from the GitHub		
2) Compile Project source code 	
3) Execute Unit Test Cases
4) Perform Code Review using SonarQube		
5) Package the application (jar/war)  
6) Upload Build Artifact in Nexus 	
7) Deploy the Application in Server

DevOps is a process/culture that IT companies are following now a days to develop and deliver the project to clients with high quality.	

Development Team -> responsible for project development (coding)
Testing Team -> responsible for project functionality testing (verification & validations)

Operations Team -> Responsible for Build & Deployment process 

DevOps is a process which is used to collaborate development team work & operations team work. 
Using DevOps process we can simplify application Build & Deployment process

=== Challenges in Manual Process ===

> Every day we need to deploy latest code	
> Deploy code in multiple environments	
> Takes lot of time
> Repeated work	
> Error Prone	
	
 ---- to overcome the above challenges we use Jenkins

CI/CD    Continuous Integration   Continuous Delivery/ Continuous Deployment

- when I make some code changes in GitHub repository, immediately it should be deployed
- CI/CD is one of the trending approach in software development
- CI/CD is used to simplify and automate build & project deployment & delivery process

Continuous Integration -> when code changes happen - it should be ready to be  tested
Continuous Delivery - Keep it ready to release (in Nexus Repository - war/ jar file)
Continuous Deployment - Deploy the Project to Product (after getting approval from client)

GitHub Repo URL   -- AWS Virtual Machine (EC2 Instance) - Tomcat

Manual Deployment:	
1. Download Code from GitRepo	
2. Create war / jar file (mvn clean package)
3. Upload war file into tomcat server (deployment)

Automation
Git Repo --- Jenkins Server (EC2 Instance + Jenkins Install)   --- Apache Server

pipeline {
    agent any

    environment {
        // Define your configuration variables here
        REGISTRY_CREDS   = 'dockerhub_login' // The ID of your credentials stored in Jenkins
        IMAGE_NAME       = 'myapp/springboot-app'
        IMAGE_TAG        = "${BUILD_NUMBER}"
        CONTAINER_NAME   = 'springboot-app-container'
        APP_PORT         = '8080'
    }

    tools {
        // Matches the name defined in Manage Jenkins -> Tools
        maven 'M3' 
    }

    stages {
        stage('Clone Repository') {
            steps {
                echo 'Cloning Spring Boot application from GitHub...'
                // Cleans the workspace and checks out the repository defined in the Jenkins job configuration
                checkout scm
            }
        }

        stage('Maven Build') {
            steps {
                echo 'Cleaning, compiling, and packaging the application...'
                // Runs unit tests and builds the executable .jar file inside the target/ folder
                sh 'mvn clean package'
            }
        }

        stage('Build Docker Image') {
            steps {
                echo "Building Docker image: ${IMAGE_NAME}:${IMAGE_TAG}..."
                // Builds the image using the Dockerfile located in the root directory
                sh "docker build -t ${IMAGE_NAME}:${IMAGE_TAG} -t ${IMAGE_NAME}:latest ."
            }
        }

        stage('Deploy Container') {
            steps {
                echo 'Deploying application to Docker container...'
                
                // 1. Stop and remove the existing container if it is already running
                sh """
                    if [ \$(docker ps -aq -f name=^${CONTAINER_NAME}\$) ]; then
                        echo "Stopping and removing existing container..."
                        docker stop ${CONTAINER_NAME}
                        docker rm ${CONTAINER_NAME}
                    fi
                """
                
                // 2. Start the new container with the newly built image
                sh "docker run -d -p ${APP_PORT}:${APP_PORT} --name ${CONTAINER_NAME} ${IMAGE_NAME}:${IMAGE_TAG}"
                
                echo "Application successfully deployed and running on port ${APP_PORT}!"
            }
        }
    }

    post {
        success {
            echo "Pipeline completed successfully!"
        }
        failure {
            echo "Pipeline failed. Review the logs above to troubleshoot."
        }
    }
}

# Step 1: Use a lightweight JRE base image
